# 列車人狼 · Train Werewolf

> 疾走する列車、殺意が潜む旅。あなたは生きて駅に着けるか？

**Minecraft Bedrock Edition** をベースにした多人数オンライン推理対戦ゲームAddon。プレイヤーは同じ列車に乗り合わせ、その中に**殺人者**が紛れ込んでいる——タスクをこなし、ゴールドを稼ぎ、アイテムを買い、犯人を探し出す。どちらかが勝利するまで。

> **5～15人**に対応、1試合約**10分**；専用の列車マップ付き。

## ゲーム概要

列車に乗り込むと、システムが3つの役職のうち1つをランダムに割り当てます：

| 役職 | 人数 | 目標 |
|------|:--:|------|
| 🩸 **殺人者** | 1 人 | 乗客を全員始末し、身分を隠す |
| 🔫 **警官** | 1 人 | 乗客を守り、殺人者を見つけ出して殺す |
| 🧑 **乗客** | 残り全員 | 生き延び、警官が殺人者を見つけるのを助ける |

**勝利条件**

- 殺人者が死亡 → **乗客の勝利**
- 乗客が全員死亡 → **殺人者の勝利**
- 時間切れ時に乗客が生存 → **乗客の勝利**

**1試合の流れ**：乗車 → 役職をランダム配分 → システムが制限時間付きタスクを配布（時間切れは死亡）→ タスクを完了してゴールドを稼ぎ、ショップでアイテムを購入 → 勝敗が決まる → ホームに戻って次の試合の準備。

プレイヤー向けの詳細はリポジトリ内の [PLAYER_GUIDE.ja_JP.md](./docs/PLAYER_GUIDE.ja_JP.md) を参照してください。

## 特徴

- **完全な三者対戦**：殺人者 / 警官 / 乗客。それぞれ専用の仕組みと勝利条件を持つ
- **タスクシステム**：6種類のタスク（換気 / トイレ / 睡眠 / 食事 / 水分 / 交流）。制限時間付きカウントダウンで、時間切れは即死
- **経済とショップ**：ゴールドは自然増加 + キル報酬；**殺人者専用の携帯ショップ** + マップ上の**自動販売機**
- **豊富なアイテム**：ダガー、リボルバー / デリンジャーと弾丸、バット狂乱、毒薬と**フードトレイへの毒盛り**、手榴弾、電源切断装置、魔法の巻貝（役職を調べる）、父の懐中時計（1回だけ死を回避）など
- **カスタムブロック**：**鍵付きドア**（鍵 / ピッキングツール / バール連動）、**自動販売機**（マルチブロック構造）、**フードトレイ**（ランダムで食べ物をドロップ）
- **死体とネームタグのシステム**：死亡後は名前付きの死体が残り、メモの内容も死体に残る
- **完全多言語対応**：簡体字中国語 / 繁体字中国語 / English (US) / English (UK) / 日本語を内蔵（`zh_CN`、`zh_TW`、`en_US`、`en_GB`、`ja_JP`）
- **ビジュアル設定パネル**：管理者が棒を持って右クリックするだけで、マップ座標・タスクパラメータ・ショップ商品などを設定できる
- **2ブランチ保守**：同じゲームプレイのコードで国際版とNetEase版の両方に対応（異なるのはスクリプトAPIのバージョンのみ）
- **オプションの音声連携**：[VoiceCraft](https://gitlab.avion.team/voicecraft/VoiceCraft) を導入すると近距離ボイスが自動で有効化（生存者は32ブロック、スペクテイター同士は相互接続かつ生存者とは完全に分離）；導入しなければ**影響ゼロ**で、VoiceCraft側のコードを一行も変更する必要がない

## クイックスタート

### プレイヤー / サーバー管理者

1. Addonを入手する。リポジトリは現在**ソースディレクトリ**の形で保守されており（`BP/` ビヘイビアパック + `RP/` リソースパック）、パッケージングスクリプトはまだ付属していません。
2. インストール方法は次のいずれか：
   - **インポート**：`BP/`、`RP/` をそれぞれ `.mcpack`（または統合して `.mcaddon`）にパッケージし、ゲーム内でインポートする；
   - **開発ディレクトリからの読み込み**：`BP/`、`RP/` を Minecraft の `development_behavior_packs` / `development_resource_packs` ディレクトリにコピーする（下記「ローカルデバッグでの読み込み」を参照）。
3. ワールド設定でそのビヘイビアパックを有効にする（リソースパックは自動で連動します）。
4. 付属の**列車マップ**を使うか、自分で建築して以下の手順で設定する。

### 開発者

```bash
git clone https://github.com/xiaopa-baka/train-werewolf-addon.git
cd train-werewolf-addon

# 1) ブランチを選択：main = 国際版；netease = NetEase版
git checkout main

# 2) 現在のブランチに合ったスクリプト型をインストール（ブランチ切替後は必ず再インストール）
npm install

# 3) 型チェック（本プロジェクトは型検証にのみ tsc を使い、コンパイルはしない）
npx tsc --noEmit
```

### ローカルデバッグでの読み込み

`BP/`、`RP/` をそれぞれ Minecraft の `development_behavior_packs` / `development_resource_packs` ディレクトリ（ゲームの `com.mojang` データディレクトリ内）にコピーすれば、実機でそのまま読み込めます；スクリプトを変更した後はワールドに入り直せば反映されます。

> **NetEase版**：`BP/`、`RP/` を MC Studio の AddOn 作業ディレクトリにコピーしてください。
> 反復を速めるために「先に消去してからコピー」するローカルスクリプトを自分で書くことをお勧めします——本リポジトリにはそのようなスクリプトは付属していません（バージョン管理にも含まれていません）。

## 2つのブランチ：国際版 / NetEase版

同じスクリプトとテキストを使い、異なるのはスクリプトAPIのバージョンだけです：

| 項目 | `main`（国際版） | `netease`（NetEase版） |
|---|---|---|
| `min_engine_version` | `[1, 26, 50]` | `[1, 21, 120]` |
| `@minecraft/server` | `2.10.0` | `2.3.0` |
| `@minecraft/server-ui` | `2.2.0` | `2.0.0` |
| BP `capabilities` | `["script_eval"]` | なし |
| `package.json` devDependencies | 2.10.0 / 2.2.0 | 2.3.0 / 2.0.0 |

**取り決め**

- `main` は**国際版の長期保守メインライン**；機能とバグ修正は2つのブランチ間で同期させること（バージョン番号の差異を除く）。`cherry-pick` でスクリプトの一貫性を保つことを推奨。
- ブランチを切り替えると `node_modules` がブランチと一致しなくなるため、**必ず `npm install` をやり直す**こと。
- **NetEase版の既知の制限**：カスタムブロックのインタラクション（鍵付きドア、自動販売機のマルチブロック）は**NetEase側での専用対応と実機テストがまだ行われていません**。この部分のコードは当面、国際版と同一です。

## 管理者向けガイド

### 1. マップとルールの設定

ゲームに入ったら設定用の棒を入手し、棒を持って**右クリック**で設定パネルを開き、順に設定します：

1. **ゲーム全体設定**：自動開始、開始遅延、最低人数、ゲーム時間、タスクパラメータ、ゴールド成長率、試合内スタミナ / ジャンプのオンオフ、天候のオンオフ
2. **マップ領域設定**：ホーム、先頭車両の座標、列車エリア、換気エリア、トイレ地点、ランダムテレポート地点
3. **食べ物 & 飲み物設定**：タスクで有効な食べ物と飲み物のリスト
4. **ショップ設定**：殺人者ショップと自動販売機の商品と価格
5. **オプション：音声設定**（ワールドに VoiceCraft が導入され、サーバーに接続済みの場合のみ、メインメニューにこのボタンが追加されます）：生存者の音声半径を調整、デフォルト32ブロック（4～128、ステップ4）

### 2. 試合開始

- **自動**：全員が列車内にいて人数が条件を満たすと、自動でカウントダウンして出発
- **手動**：管理者が `/lw_p1:start` を実行

## オプション機能：ボイスチャット（VoiceCraft）

本ゲームプレイは [VoiceCraft](https://gitlab.avion.team/voicecraft/VoiceCraft) の近距離ボイスに対応しており、人狼ゲームの要件に合わせて3つのルールを実装しています：

| 場面 | 効果 |
|---|---|
| 生存者 ↔ 生存者 | 半径内で互いに聞こえる（デフォルト **32 ブロック**、管理者が設定パネルの「音声設定」で調整可能） |
| スペクテイター ↔ スペクテイター | **距離制限なし**、次元をまたいでも互いに聞こえる |
| 生存者 ↔ スペクテイター | **双方向で完全にミュート**（音声パケットすら送信しない） |

- **完全にオプション**：VoiceCraft を導入しない場合、本プロジェクトは**一切の動作をしません** —— タイマーを登録せず、データを送信せず、ゲームプレイや状態を変更せず、設定メニューにも「音声設定」は現れません。
- **ゼロ改修での接続**：すべての適配は本プロジェクトのスクリプト内（`BP/scripts/integration/voiceCraft.js`）だけに書かれており、VoiceCraft のアドオンとそのサーバー設定は**一行も変更する必要がありません**。そのため上流の addon のバージョン更新の影響を受けません。
- **利用の前提**（すべて必須）：① 各プレイヤーが VoiceCraft クライアントAppをインストールする；② 誰かが VoiceCraft サーバーを稼働させ、プレイヤーとMCワールドの両方からアクセスできる（グローバルIP / UDPポートマッピング / 公式ホスティング）；③ ワールド側に VoiceCraft アドオンを導入する（`Basic` + 対応する転送方式の `Core.McWss` または `Core.McHttp`）。初回参加時は VoiceCraft の手順に従って `/voicecraft:vcbind <バインドコード>` で一度バインドする必要がありますが、その後は**ワールドに入り直しても、VoiceCraft クライアントAppを再起動しても再バインドは不要**です（バインド記録はワールドの動的プロパティに保存されます；クライアント再起動後は VoiceCraft クライアントが永続保存している UserGuid によってあなたを認識します；`/lw_p1:voice_forget` を実行したプレイヤーだけが再バインドが必要です）。
- **国際版のみ**：NetEase版には `/connect` トンネルがないため、この機能は利用できません（「2つのブランチ」を参照）。

## よく使うコマンド

| コマンド | 効果 |
|---|---|
| `/lw_p1:start` | 手動で試合開始 |
| `/lw_p1:end` | 現在の試合を強制終了（いつ実行しても終了処理を行う） |
| `/lw_p1:clear_corpses` | すべての死体とネームタグを削除 |
| `/lw_p1:voice_status` | 音声連携の状態を確認：接続の有無、現在のチャンネルビットマスクと音声半径、バインド記録 |
| `/lw_p1:voice_resync [対象]` | チャンネルと音声半径を再送信し、対象の現在のバインドをワールドプロパティに書き戻す（再入場時に自動で復元）。対象は**プレイヤーセレクター**（Tabで補完あり）：**対象を省略 = すべてのバインド記録を書き戻す（オフラインプレイヤーを含む）**、`@a`=全オンラインプレイヤー、`@s`/`@p`/`@r`/オンラインプレイヤー名=指定プレイヤー |
| `/lw_p1:voice_forget [対象]` | 音声バインドを解除：ワールドプロパティから対象の id を削除するだけで、**ミュートは一切行いません**；このセッション中の音声はそのままですが、再入場（またはクライアントAppの再起動）時には `/vcbind` をやり直す必要があります。対象の指定方法は上記と同じで、**対象を省略 = すべてのバインド記録を消去（オフラインプレイヤーを含む）**、自分を消す場合は `@s` と書きます |

> `voice_*` の4つのコマンドは VoiceCraft が導入されている場合にのみ実際に機能します；未導入の場合は「VoiceCraft を検出できません」と返すだけで、エラーにはなりません。

## プロジェクト構成

```
demo/
├── BP/                         # ビヘイビアパック
│   ├── manifest.json
│   ├── blocks/                 # カスタムブロック（鍵付きドア / 自動販売機 / フードトレイ）
│   ├── entities/               # 弾丸 / 死体 / 爆竹 / 手榴弾 / ピストル / ネームタグ
│   ├── items/                  # カスタムアイテム
│   ├── loot_tables/            # 空のドロップテーブル
│   ├── texts/                  # BPパッケージ名の多言語
│   └── scripts/                # すべてのロジックスクリプト（ES Module）
│       ├── main.js             # エントリー：各モジュールを import するだけ
│       ├── core/               # hud / state / i18n / itemIcons
│       ├── game/               # lobby / gameFlow / gameEnd / environment / corpse
│       ├── gameplay/           # tasks / props / shop / inGame / guideBook
│       ├── blocks/             # keydoor
│       ├── config/             # worldConfig（データ）/ configUI（画面）/ configExtensions（オプションモジュール入口）
│       └── integration/        # オプション機能モジュール（voiceCraft：VoiceCraft 音声連携）
├── RP/                         # リソースパック（モデル / アニメーション / テクスチャ / サウンド / テキスト）
├── package.json                # devDependencies のみ（型定義 + tsc）
├── tsconfig.json               # 型チェック設定（noEmit）
└── docs/                       # プレイヤー向けドキュメント
│   ├── PLAYER_GUIDE.zh_CN.md   # プレイヤーガイド（簡体字中国語）
│   ├── PLAYER_GUIDE.zh_TW.md   # プレイヤーガイド（繁体字中国語）
│   ├── PLAYER_GUIDE.ja_JP.md   # プレイヤーガイド（日本語）
│   └── PLAYER_GUIDE.en.md      # Player Guide (English)
```

> スクリプトは領域ごとに階層化され、入口の `BP/scripts/main.js` は import のみを行うため、機能モジュールを特定しやすい。
> `config/` と `integration/` の間は**逆登録**になっている：オプションモジュールは自分の設定入口を `configExtensions.js` に登録し、設定画面は具体的なモジュールを一切知らない —— `integration/` を削除しても設定画面やその他の機能には影響しない。

## 開発ガイド

### 型チェック

```bash
npx tsc --noEmit   # 0 error なら通過
```

すべてのスクリプトファイルの先頭に `// @ts-check` を付け、`tsconfig.json` の `allowJs + checkJs` と組み合わせて静的検証を行います。

### 注意事項

- **相対インポートには必ず `.js` 拡張子を付ける**（例：`import "./config/worldConfig.js"`）。そうしないと実行時に `ERR_MODULE_NOT_FOUND` になります。
- **ScriptAPI 2.x** の書き方を使う：`world.afterEvents.worldLoad`、`world.getPlayers()`、`entity.isValid`（プロパティ）、`runCommand` など。旧インターフェースは避けてください。
- `beforeEvents` ではワールドを確実に変更できない（アイテムの付与 / エンティティの削除など）ため、`mc.system.run()` で次のフレームに遅延させる必要があります。
- プレイヤー向けのテキストは必ず `core/i18n.js` の `t()` を通して出力し、`RP/texts/` の5つの言語ファイル（`zh_CN`、`zh_TW`、`en_US`、`en_GB`、`ja_JP`）に対応するキーを追加してください（5つのファイルは厳密にミラーリングする必要があります：キー集合、`%s`、`§` コード、`\n` の位置を一致させる）。
